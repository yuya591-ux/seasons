対象: 本家 `seasons`（WebGL版 / https://yuya591-ux.github.io/seasons/ ）

- 街の建物 `townChildren` **1646**／住民194／輪郭161／公園136／室内125／観覧車112／木80／寺63
- そのうち**「重い32件」だけで809メッシュ**＝全体の約38%
- 既に1メッシュに統合済みの建物が1087棟（＝易しい統合は完了済み）

**結論（発熱の主因）**: JS時間は全状態1ms台で健全。三角形数も節度あり。残る主因は
**①描画コール2000超のCPU提出コスト**（iOSはANGLE→Metal変換で1コールが高い）と
**②CSS合成5層のコンポジタ仕事**（ネイティブ解像度で約12MP/フレーム）。
CPU4倍条件で解像度が自動的に1.6→1.48→1.24へ落ちている事実は、**発熱と「画質が悪い」が同じ根**であることを示す。

### この計測の限界（正直に）

デスクトップGPUは桁違いに速いため、**画素側（CSS合成・解像度・ブルーム）のGPU負荷はfpsに現れない**。そこは解析モデル＋実機A/Bで判断する。最終判定は実機1回（第5部）。

## #7 CSS合成層 5→3

`src/engine/town3dViewer.js` に `FULLCSS` スイッチを実装。既定では「紙目2層め（粗いにじみ）」と「縁のにじみ」を**そもそも作らない**。`?fullcss=1` で従来の5層に完全復元できる（コードもCSSも残してあるので非破壊）。
机上のGPUでは画素側の負荷がfpsに出ないため、効果の判定は実機A/Bへ委譲（`docs/qa/2026-07-28_実機確認.md`）。

## #9 着地の足元の灰色 — 原因は想定と別物

`docs/qa/2026-07-28/09_着地_安定後.png` を確認。**停車中のトラックの真上／中に着地しており、白い車体が画面の下半分を塞いでいる**。着地アニメ中の一時的なものではなく、着地地点の選び方の問題。「灰色の地面」ではなく「車」だった。
→ 修正は着地地点の判定（前方に大きな物があれば退がる／横へずらす）。**未着手・可否判断待ち**。

## #10 雲海の白い塊 — 雲ではなく霧が原因

`docs/qa/2026-07-28/10_雲海_近接_b.png`（高度92m）を確認。画面の約95%が淡いベージュ一色で、雲上の島・東屋・かもめ・下界の山がすべて幽霊のようにしか見えない。
**雲の白い塊は出ていない＝#289の近接フェードは効いている。** 原因は**この高度帯の霧（大気の霞）が強すぎること**。範囲外メモに記録。

## #11 ほこりが四角い — 原因確定

```
#11 粒(Points)の材質一覧:
[{"n":160,"size":2.1,"絵柄":true},{"n":130,"size":2,"絵柄":true},{"n":150,"size":2.3,"絵柄":true},
 {"n":46,"size":0.026,"絵柄":false,"op":0.24}]
```

46個の窓辺のほこりだけ**絵柄が無い**。絵柄の無い粒はWebGLの既定で四角に描かれる。他の3種は絵柄つきで丸い。→ 丸い絵柄を1枚与えれば直る。**未着手・可否判断待ち**。
