## 1. 総評

**「マネキンのように見える」は印象ではなく、実装がそうなっている。** 数字と画像で裏が取れた。

街に居る人物は **244体**（ほかに犬猫馬が18体。前回検収の「262体の人物」は `userData.headG` を四足獣も持つための取り違えで、今回訂正した）。
このうち最も作り込んだ層 `makeResident` **73体の 67%（49体）に、振れる脚も手も無い**。江戸20体・戦国18体・雲海7体は**全員**が該当する。
真っ黒に塗ったシルエットで測ると、着物姿は**脚が割れる行 0/139・腕が胴から離れる行 0/150**。つまり輪郭に手足がまったく現れない。真横から見た充填率は **0.77**（9体中の最悪級）で、**厚みのない板**である。

さらに深刻な不具合を1件見つけた。**現代homeの高品質住人は10体すべて、頭が肩から約50cm離れて宙に浮いている**（`chars/頭が浮いた住人_正面.png`）。
9092行のうなずき動作が、等身是正前の古い基準値 `1.6` を書き戻しているためで、一度会話状態に入ると**元に戻らない**。歩いて近づくといちばん先に出会うのがこの10体である。

そして**主人公が二重に壊れている**。街に立っているのは厚み0の一枚絵9体（真横から見ると完全に消える）、操作している自分には姿が無い。
`hero/立ち絵と住人_並び.png` が今回いちばん重い1枚で、**同じ作品の中で主人公だけが「あるべき造形」で描かれ、住人はそこに遠く届いていない**ことが一目で分かる。

**一方で、性能は制約にならない。** 実測でキャラは描画コールの26〜28%を占めるが、内訳は極端に偏っており、
**高品質住人73体に1体6メッシュ足しても +2.6%**（同時に描かれるのが9体だけのため）。しかも #6 で見積もったとおり、

高いのは現代homeの歩行者 `makePeep` だけ（1メッシュ +42コール）。

**したがって、抑える理由は無い。作り直すべきである。**

## 2. 強み（壊してはいけないもの）

1. **輪郭線の仕組みが既にある**。`addOutlines(0.009)`（6785行）が各メッシュの裏面を法線方向に押し出した複製で主線を作る。セルルックの根幹で、**造形を増やしても自動で線が付く**。
2. **胴・腕・脚が「一枚の連続メッシュ」**。`loft()`（6776行）が断面リングを繋ぐ方式なので、球の寄せ集めではない。**リング座標を足すだけで形を変えられる**＝改造に強い。
3. **顔がテクスチャで、しかもキャッシュされている**。`makeFaceTex`（6537行）が128×128に瞳・虹彩・つや・眉・鼻・微笑・頬の赤みを描き、虹彩色×髪色でキャッシュ。**表情を増やしても描画コールは増えない**。
4. **歩き癖の個体差の器が既にある**。`makePeep` は `gaitAmp` / `armAmp` / `cadMul` / `bob` / `sway` / `armLead`（6598〜6606行）を持つ。**同じ器を `makeResident` に移植すればよい**。
5. **距離カリングが強力に効いている**。73体の住人のうち同時に描かれるのは9体。**近景だけを豪華にする設計が、そのまま性能設計になっている**。
6. **2Dの立ち絵が、目指すべき絵柄の見本として既に存在する**。細い均一な輪郭線・流れのある髪・表情・脚と手と靴。**新しく画風を決める必要がない**。
7. **接地影がある**。`resShadowGeo`（6875行）で足元が締まる。浮きの防止が既に入っている。
8. **大正エリアだけは配役がまともに機能している**。男女7:11で、女性・書生・紳士が並ぶ。**他エリアの目標形として使える**。

## 3. 弱点

### A. 致命的（今すぐ直すべき）

**A1. 現代homeの高品質住人10体すべてで、頭が肩から離れて宙に浮いている**
- 根拠: `docs/qa/2026-07-31/chars/頭が浮いた住人_正面.png` / `頭が浮いた住人_横.png`。実測で `headG.position.y` が **1.596〜1.603**（正しくは 1.11）。該当 **10/10体（100%）**
- 真因: 9092行 `u.headG.position.y = 1.6 + Math.sin(…)` が、6873行の等身是正（`headG.position.y = 1.11`）より前の古い基準値を書き戻している。1.11 に戻す処理が無いため**永久に浮いたまま**
- 影響: 歩行で最初に出会う近景の人物がこれ。**他の何を直しても、近づいた瞬間に壊れる**

**A2. 高品質住人73体のうち49体（67%）に、振れる脚も手も無い**
- 根拠: `charcast.txt` の #5。江戸 20/20体・戦国 18/18体・雲海 7/7体・大正 4/18体
- 真因: `buildLegs()`（6795行）と手の追加（6792行）は `dress`/`blouse`/`modern`/`suit` の分岐だけ。`kimono`/`hakama`/`armor`（6798〜6811行）は裾に潰した球を2つ置くだけ（6802行）
- 影響: **歩いても脚が振れない＝滑る人形**。着物31体・甲冑14体・袴4体が全滅

**A3. 侍の刀・足軽の槍が、手から離れて宙に浮いている**
- 根拠: `chars/armor_正面.png`。小道具は身体に直接 `add`（6861〜6864行）され、握る手が存在しない
- 影響: 武装した人物のシルエットの要が成立していない

### B. 重い（マネキン感の直接の原因）

**B1. 体型の個体差がゼロ。全員が同じ体型の拡大縮小**
- 根拠: 6872行 `body.scale.set(0.82, 0.72, 0.82)` は全員共通の固定値。6876行 `g.scale.setScalar((cfg.scale||1) * (0.98 + R()*0.12))` は一様スケール±6%

**B2. 作り込んだ層のほうが人間から遠い（品質の序列が逆転）**
- 根拠: 肩幅÷身長は `makeResident` **0.178** に対し簡易版 `makePeep` **0.238**（実際の人間は0.23〜0.26）。
  シルエットの脚割れは `crowd`/`walker` が **140/140（満点）**、`kimono` が **0/139**
- 影響: **2メッシュの簡易版が、24メッシュの高品質版にシルエットで完勝している**

**B3. 江戸と戦国に女性・子供・老人が1人も居ない**
- 根拠: `charcast.txt` の #4。江戸20体＝侍6/髷の町人8/笠の行商6、戦国18体＝農夫10/足軽6/武者2。**全員が男性像**
- 女性が居るのは大正の7体のみ。しかも**全員が同じ「ボブ＋ワンピース」**

**B4. 主人公が二重に存在し、どちらも成立していない**
- 根拠: `hero/立ち絵_横.png` は**背景一色**（板が真横で消える）。`hero/アバター不在_zoom*.png` 4枚は歩行中に自分の姿が無いことの記録。カメラ前方 2.9m に何も無く、レイキャストで最も近い物は 7.0m 以遠
- 立ち絵の材質は `MeshBasicMaterial`（6748行）＝**陰影が乗らない**。板2.1mのうち絵は1.712mで、**足元が板の下端から0.21m浮いている**（接地影は板の原点にあるため約19cmずれる）

**B5. 頭身がコードの意図と食い違っている**

- 影響: 意図と実物がずれたまま調整が積み重なっている。**セルルックとしては頭が大きいほうが正しい**ので、直すべきはコメントと目標値のほう

## 4. 設計案

### (a) 体型と身長の個体差の与え方 — 新規メッシュ0個

現行の `body.scale.set(0.82, 0.72, 0.82)`（6872行）を、**個体ごとに振れる3つの値**に置き換える。

```js
// 案: 体格をひとつの「型」として持つ（値だけ。メッシュは増えない）
const BUILD = [
  { name: 'ほっそり', w: 0.74, h: 0.74, belly: 0.94, stoop: 0.00 },
  { name: 'ふつう',   w: 0.82, h: 0.72, belly: 1.00, stoop: 0.02 },
  { name: 'がっしり', w: 0.92, h: 0.70, belly: 1.10, stoop: 0.00 },
  { name: 'ふくよか', w: 0.98, h: 0.68, belly: 1.22, stoop: 0.04 },
  { name: 'こども',   w: 0.78, h: 0.58, belly: 1.06, stoop: 0.00, head: 1.14 },
  { name: 'としより', w: 0.80, h: 0.66, belly: 1.02, stoop: 0.13 },
]
body.scale.set(b.w, b.h, b.w * 0.98)        // 6872行を置き換え
headG.scale.setScalar(0.9 * (b.head || 1))   // 6873行。子供だけ頭を大きく＝セルルックのデフォルメ
body.rotation.x = b.stoop                    // 猫背（老人）
```

- **胴回り**は `loft()` のリング半径に `belly` を掛けるだけ（6799行など。リングは既に配列なので係数を掛ける1行で足りる）
- **身長**は既存の `g.scale.setScalar()` の振れ幅を ±6% → **±14%** へ広げる（`makePeep` と同じ幅。6876行の係数のみ）
- **子供は頭を大きく**する。承認記録3のとおり頭身を上げて写実へ寄せるのではなく、**下げてデフォルメを強める**方向。実測の4.2頭身は子供表現としてむしろ正しい
- **コスト: 新規メッシュ0個。描画コール増 0**

### (b) 脚と手をすべての衣装に通す — 新規メッシュ0個

いま `buildLegs()` / 手を呼んでいないのは `kimono` / `hakama` / `armor` の3分岐（6798〜6811行）。ここを**時代考証の側から**解く。

| 衣装 | 変更 | 根拠 |
|---|---|---|
| `kimono`（町人・浴衣） | 裾を膝下で止め、`buildLegs(skin, 0.05)` を呼ぶ | 町人の普段着は裾をからげて歩く。**脚が出るのが本来** |
| 新 `kimono-short`（職人・農夫） | 半纏＋股引。`buildLegs(botM, 0.055)` | 江戸の職人・戦国の野良着は**丈が短く脚絆で脚が出る**（#6） |
| `hakama`（書生） | 袴の下端を足首上で止め、`buildLegs` を呼ぶ | 袴でも足袋と足元は見える |
| `armor`（侍・足軽） | 佩楯（腿の防具）＋脛当てとして `buildLegs(botM, 0.06)` | 甲冑は**もともと脚の防具が独立している** |
| 全衣装の腕 | `buildArms(mat, true)`（袖のみ）を廃し、**袖のロフト＋手**の形へ統一 | `buildArms` の `wide` 分岐（6791行）に手の追加1行を足すだけ |
| たすき掛け（農婦・女房） | `buildArms(mat, false)` を呼ぶ | 袖をたくし上げる所作。**手が自然に出る** |

- `buildLegs` / `buildArms` は既存関数。**呼ぶ場所を増やすだけで新規メッシュは増えない**（脚2＋手2＝4メッシュは、いま「潰した球2つ」で使っている2メッシュとほぼ相殺）
- 副次効果として **`legs` 配列が埋まるので、既存の歩行アニメがそのまま効く**（滑る人形の解消）
- 小物（刀・槍・杖）は `g` 直付け（6861〜6864行）をやめ、**`arms[i]` の子にして手の位置へ**。A3が同時に解ける

### (d) 主人公の3D案と、歩行時の出し方

**方針**: 2Dの立ち絵（`makeGirlStandee` 6745行）は**削除せず非破壊で温存**し、`placeGirl` の呼び出し（6962・6985行）を段階的に減らす。
新しく **3Dの主人公 `makeHero()`** を `makeResident` の派生として作る。

- **造形**: `makeResident` に (a)(b) を適用したうえで、主人公だけ +6〜8メッシュを許す
  （前髪の房を分ける／リボンか髪留め／鞄／靴の作り分け）。立ち絵の絵柄（`drawHarborGirl2D`）を3Dの造形指示として読む
- **顔**: `makeFaceTex`（6537行）に**主人公専用の1枚**を追加。虹彩色×髪色のキャッシュ機構にそのまま乗る＝**描画コール増0**
- **背丈**: 立ち絵の実測 1.712m は住人（1.39m）より23%大きい。**主人公は住人と同じ尺度に揃える**（1.45m前後＝少し背の高い若者）。
  いまの「主人公だけ大きい」状態は世界の縮尺を壊している
- **歩行時の出し方**: カメラは立ち位置の 2.9m 後ろ・1.1m 上（45〜67行 `FLY.walkBack` / `walkUp`）。ここに `makeHero()` を1体置き、
  - 移動中は `legs`/`arms` を既存の歩行アニメで振る（`makePeep` の `gaitAmp` 等を流用）
  - 立ち止まると `sitAmt`（既存。`__town3dSit` で観測できる）に連動して腰を落とす
  - **ズーム0.4（最も寄る）では頭部が画面を覆う**ので、`zoom < 0.7` では主人公を半透明→非表示にフェード（既存の距離フェードと同じ仕組み）
- **コスト**: 主人公は**常に1体だけ描かれる**。30メッシュでも **+30コール ≒ +1.8%**
- **副次効果**: 9624行で「アバター不在なので何もない地面から衝撃波が広がる」ため撤去した**着地の砂ぼこりが復活できる**

### どの層まで作り直すかの推奨（#11 の実測に基づく）

| 層 | 体数 | 推奨 | 理由 |
|---|---|---|---|
| **`makeResident`（高品質住人）** | 73 | **全面的に作り直す。制限を設けない** | 同時に描かれるのが9体だけ。1体+6メッシュで **+2.6%**。主要改善は新規メッシュ0個 |
| **主人公（新規 `makeHero`）** | 1 | **作る。30メッシュまで許す** | 常に1体だけ。**+1.8%** |

| **`makePeep`（現代homeの歩行者）** | 90 | **メッシュ数を増やさない。形だけ作り替える** | 71〜74体が常時描画。1メッシュが **+42コール**。ここだけが唯一の制約 |
| **`makeGirlStandee`（2Dの立ち絵）** | 9 | **非破壊で温存しつつ出番を減らす** | 3Dの主人公ができれば役目が重複する |

**上限（窓辺の実測 総コール1831 に単価を当てて導出）**

| 層 | 現行の1体あたりメッシュ | 上限 | そのときの窓辺の描画コール |
|---|---|---|---|
| `makeResident` | 24 | **61メッシュ**（現行の2.5倍） | 2101（発熱対策前の「重い」水準に並ぶ） |

→ `makeResident` は **61メッシュまで**使える。設計案(a)(b)(c)の合計は現行24＋2〜4程度なので、**上限の半分にも届かない**。

**総評としての推奨**: 裕也さんの条件（「重くなる・画質が落ちる・発熱するなら抑える」）に照らすと、**抑える必要があるのは `makePeep` の1層だけ**。
残る4層は作り直しても合計 **+5%未満**に収まる。**したがって「マネキン脱却」は全面的に進めてよい。**

## 6. この評価の限界

- **時代エリアに降りたときの単価を測っていない**。現代homeの視点では `mkCrowdPerson` 56体と `cityWalker` 25体が1体も描かれないため、単価が0と出た。江戸・戦国に着地すればこの2層が主役になる。**#11-b を時代エリアでもう一度測るまで、この2層の予算は未確定**
- **フレーム時間は判断に使えない**。開発機の値は 173〜225ms と不安定で、idle の間引きも混ざる。**判断はすべて描画コールで行った**
- **実機（iPhone）で測っていない**。描画コールの比率は端末に依らないが、発熱の体感は別途の実機確認が要る
- **前回検収の未反映コミットが残っている**。今回の評価もローカル現行版に対するもので、公開版とは別物
