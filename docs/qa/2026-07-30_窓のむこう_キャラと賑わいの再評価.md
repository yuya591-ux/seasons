## 調査で分かったこと（すべて実物を読んで確認）

### 時代エリアの住人は中心の輪の中だけにいる

```js
const placeEra = (cx, cz, n, factory) => { for (let i = 0; i < n; i++) {
  const a = (i / n) * 6.2832 + R() * 0.6, rr = 8 + R() * 22   // ← 中心から8〜30mの輪のみ
  placeResident(cx + Math.cos(a) * rr, cz + Math.sin(a) * rr, factory()) } }
```

エリア自体は大正 r112・江戸 r124 まで広げてある（`area-expansion` の記録）。**外側に足した新地区には人が1人も置かれていない**可能性が高い。これは今回いちばん確かめたい仮説。

### 歩行は「引いた三人称の浮遊カメラ・アバター無し」

```js
walkBack: 2.9, walkUp: 1.1, walkAhead: 7.2,  // 既定zoom1.56で実効back≈4.5 / up≈1.4
walkFov: 78,  walkCamLag: 0.18,  walkCamFollow: 0.9
```

ズームは 0.4〜3.0。**絞れば一人称寄り、引けば肩越しの眺め**になる。ただし自分の姿は無い（アバター無し）。今回は「いまの歩行体験の評価」であり、設計そのものは変えない（承認記録2）。

### UIの構成要素

`.gate`（起動の間）／`.hud` `.hud__scene` `.hud__audio`／`.modepill`（現在地）／`.stagedots`（段階表示）／`.panel`（設定・ふりかえり）／`.gallery` `.gallery-filter`（情景メニュー）。`src/style.css` に定義。

### 使える調査フック（既存・アプリ変更不要）

`__town3dFigShot`（人物の隔離接写・`?dev=1` 限定）／`__town3dCrowdShot`（群衆の一人を接写）／`__town3dShotAt`（任意のカメラで1枚）／`__town3dGroundAt`（地面の高さ）／`__town3dCalls`（画面に描かれる物の内訳）／`__town3dDbg`（自機の状態）／`__town3dTownAudit`（配置違反）

### #9 の所見（重大）

**「窓をあける」「乗り出す」の2段は、ボタンの真ん中を指で突くとキャンバスが受け取る**（`指が当たる物: CANVAS` / `ボタン自身か: false`）。「空へ」「地上へ」の2段では正しくボタンが受け取る（`ボタン自身か: true`）。

原因は重なり順。`src/style.css:131` の `.town3d-stage` が `position: fixed; z-index: 0`、`src/style.css:860` の `.topbar` は `position: fixed` で **z-index の指定が無い**。同じ重なり階層になるため、あとから差し込まれる3Dの面が topbar より手前に来る。空・地上の段で直るのは、そのときだけ `.iconbtn--stage.is-aloft`（`src/style.css:905`）という別の指定が当たるため。

導線そのものは4段（窓をあける→乗り出す→空へ→地上へ）＋「もどる」で一貫しており、段階表示（●○○○）は窓をあけた時点から出る。ただし **flow_01〜04 では段階表示が非表示**で、窓辺に着いた人には次の一歩の存在が見えていない。
