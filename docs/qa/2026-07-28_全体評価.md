# 窓のむこう ｜ 全体評価（2026-07-28）

根拠: 本検収で実際に操作して撮った6枚（`docs/qa/2026-07-28/01_窓辺.png` `02_窓をあける.png` `03_低空飛行.png` `04_雲海.png` `05_歩行.png` `09_着地_安定後.png`）と、実測3セット（`heavy.txt` / `baseline.json` / `fact3.txt`）。

## 総評

**眺めるアプリとして、すでに完成している。** 窓辺の一枚絵は商品レベルで、水彩のグレードと空気遠近が効き、低ポリの街が「絵」として成立している。25情景すべてがエラー0で動き、全自動の巡回検証まで整っている個人プロジェクトは稀。
一方で、**「降りたあと」の作り込みが窓辺に追いついていない**。着地の第一印象、歩き出してからの行き先、近景の粒立ち。ここが伸びしろの本体。
発熱については、今回で構造が数字で見えた。**JSは全状態1ms台で健全、三角形も節度あり、カクつき率0%。残る負荷は「描画命令の数」と「画面全体に重ねる層」の2つだけ**で、犯人は絞り込み済み。

## 強み

1. **窓辺の絵の完成度** — 01/02のスクショは加工なしでそのまま見せられる。時間帯・季節・天気の移ろいが色として設計されている
2. **世界の広さと接続** — home／雲海の島々／江戸・大正・戦国が一つの空でつながり、飛んで行ける。「渡ると別の時代」という着想が効いている
3. **崩れない足腰** — `npm run smoke`（25情景）と `npm run walk`（全情景を自動操作して黒画面・配置違反・描画コール急増を検出）。1.19MBの単一ファイルを安全に触り続けられているのはこの網のおかげ
4. **性能の自己修復** — 重いと判断したら、まずブルームを落とし、次に解像度を譲る。落ち方が設計されている
5. **音の距離設計** — 祭り囃子が遠くから聞こえ、近づくと明るく開く。室内は防音がかかる

## 弱点（すべて具体箇所つき）

1. **着地カメラが物の中に入る**（`09_着地_安定後.png`）— 降り立った瞬間、停車中のトラックの真上に着地し、画面の下半分を白い箱が塞ぐ。着地地点の前方に大きな物がある場合の退避が無い。**降りる体験の第一印象を毎回損なう**
2. **窓辺のほこりが四角い**（`fact3.txt`: `{"n":46,"size":0.026,"絵柄":false}`）— 粒に絵柄が無く、WebGLの既定で四角に描かれる。他の3種の粒（160/130/150個）は絵柄つきで丸い。**この1つだけ取り残されている**
3. **音に非有限値が混入**（本検収のコンソール: 199件の `setTargetAtTime ... non-finite`）— 音量やフィルタの計算がNaNになる経路がある。実害は未確認だが、鳴り止み・途切れの原因になりうる
4. **描画命令が窓辺で1993回**（`heavy.txt`）— iPhoneはこの提出1回ずつにCPUを使う（Metalへの変換）。**発熱の主因**。内訳の特定は済んだが、大半（約1300）は道路・地面・什器など街の下敷きで、まだ束ねていない
5. **重い32件のうち9件は「建物」ではなく人の群れ**（`heavy.txt` 7〜15位・各27〜29メッシュ）— 人物の作りが重い。#285と#288の判断待ちで宙に浮いている
6. **CPUが4倍遅い条件で解像度が自動的に1.6→1.24まで落ちる**（`baseline.json`）— 「発熱」と「画質が荒い」は同じ根。負荷を下げれば画質も上がる関係
