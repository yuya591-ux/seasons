### マネキン感の疑わしい真因（3つ。すべて実装の事実）

**① 体型の個体差がゼロ。全員が同じ体型の拡大縮小。**

```js
body.scale.set(0.82, 0.72, 0.82)                       // 6875行・全員共通の固定値
g.scale.setScalar((cfg.scale || 1) * (0.98 + R() * 0.12)) // 6879行・一様スケール±6%
```

肩幅・胴回り・脚の太さ・姿勢はコード上ひとつの値しか無い。**痩せた人・恰幅のいい人・猫背の人が存在しない**。

**② 時代エリアの住人には脚も手も無い。**

`buildLegs()` と手の追加（`add(armG, SP(0.04,…), skin, …)`）は **`dress` / `blouse` / `modern` / `suit` の分岐だけ**。`kimono` / `hakama` / `armor` は裾に潰した球を2つ置くだけ（6802行）で、`legs` 配列が空のまま返る。

```js
for (const s of [-1, 1]) add(g, SP(0.057), shoeM, s * 0.06, 0.05, 0.05, 1.4, 0.5, 1.9) // 足＝球2つ
buildArms(topM, true)  // wide=true は袖のloftのみ。手を作らない
```

衣装の割り当て（6968〜6985行）から、**脚も手も無いのは**: 江戸20人全員（armor 24% / kimono 76%）・戦国18人全員（armor 58% / kimono 42%）・大正の書生（hakama 34%）・祭りと雲海の folk 全員（`buildFolk` は常に `outfit: 'kimono'`）。**歩いても脚が振れない＝滑るマネキン**になる。

**③ 江戸と戦国に女性の衣装が1つも無い。**

江戸＝侍(topknot)・笠の行商・町人(topknot|short)、戦国＝足軽(jingasa)・武者(topknot)・農夫(kasa)。**全部が男性像**。女性が居るのは大正の `dress`+`bob` だけ。老人・子供の造形も存在しない。

### 主人公が二重で、しかも実体が無い

- `makeGirlStandee`（6745行）＝ 360×720のキャンバスに `drawHarborGirl2D` で描いた**一枚絵**を `PlaneGeometry(1.05, 2.1)` に貼り、常にこちらを向かせるビルボード。材は `MeshBasicMaterial`（トゥーンでもなく陰影が乗らない）。港・駅前・街角に最大11体
- 歩行モードは**アバター無し**（45・67行に明記。9624行「アバター不在なので何もない地面から衝撃波が広がる」ため着地の砂ぼこりを撤去した経緯あり）
- つまり「主人公」は**2Dの絵として街に立っている**が、**操作している自分には姿が無い**

### 既にできている良い土台（壊さないもの）

- **輪郭線**: 各メッシュの裏面を法線方向に押し出した複製（`addOutlines(0.009)`）＝セルルックの主線
- **一体のロフト**: `loft()` が断面リングを繋いで胴・腕・脚を一枚の連続メッシュにしている（球の寄せ集めではない）
- **顔**: `makeFaceTex`（6537行）が128×128に瞳・虹彩・つや・眉・鼻・微笑・頬の赤みを描き、頭前面の薄い円筒面へ貼る。虹彩色×髪色でキャッシュ
- **歩き癖の個体差**: `makePeep` は gaitAmp / armAmp / cadMul / bob / sway / armLead を持つ（`makeResident` には無い）

### 使える調査フック（既存・アプリ変更不要）

`__town3dFigShot(yaw, cfgJson, faceZoom)`（住人の隔離接写・`?dev=1` 限定）／`__town3dCrowdShot`／`__town3dQuadShot`／`__town3dShotAt`／`__town3dGirlFront` `__town3dGirlCount`／`__town3dResPin` `__town3dPeepPin`／`__town3dDraw`（真の描画コール）／`__town3dCalls`／`__town3dZoom`。
加えて前回確立した**three の `Object3D.prototype` を包んで根のSceneを捕まえる手法**（`docs/qa/2026-07-30_窓のむこう_キャラと賑わいの再評価.md`）で、シーングラフを直接測る・実行時に材質を差し替える（シルエット撮影）ことができる。**いずれもアプリのコードは変更しない**。

## 承認記録（2026-07-31・裕也さん）

1. **成果物は評価と改善案の洗い出しまで。実装はしない**（見本の試作も今回はしない）
2. **主人公は「3Dで作り、歩行時に出す」案を設計に含める**（2Dの立ち絵は非破壊で温存しつつ出番を減らす方向）
3. **画風はセルルック維持。造形だけ大幅強化する**（頭身を上げて写実へ寄せる方向は採らない。2026-07確定の「キャラ=セルルック／背景=リアル寄り」を守る）
4. **対象の層は、性能・発熱・画質への影響を測ってから決める**。影響が出ないなら4系統すべてを対象、出るなら抑える。そのバランスの推奨を出すこと（＝第4部が第5部の前提）
